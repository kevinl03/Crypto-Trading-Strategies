\section{Experimental Setup}\label{sec:setup}

\subsection{Data Collection}

We collect live microstructure data from centralized cryptocurrency exchanges using a custom collector that polls 9~signal families via REST API every 60~seconds across 23~assets and up to 6~exchanges (Binance, Bybit, OKX, Coinbase, Kraken, MEXC). Under full signal load, the observed wall-clock cadence is approximately 110~seconds per snapshot due to API rate limits and sequential polling.

The signal families are: \texttt{spread\_matrix} (precomputed pairwise cross-venue spreads), \texttt{ticker} (best bid/ask, last price, top-of-book volumes), \texttt{orderbook} (top~20 price levels per side), \texttt{trades} (last 50~prints with buy/sell classification), \texttt{funding\_rate} (perpetual swap funding rates), \texttt{open\_interest} (perpetual open interest), \texttt{withdrawal\_status} (deposit/withdraw enabled flags and fees), \texttt{exchange\_status} (venue operational status), and \texttt{ohlcv} (1-minute candles, backfillable but excluded from training).

Data is stored as JSONL files partitioned by signal family and collection date, with each record tagged by snapshot index and UTC timestamp.

\subsection{Asset Universe}

The 23-asset universe (\texttt{VOLATILE\_COINS}) was selected for high cross-exchange spread volatility and sufficient liquidity across multiple venues. It includes major assets (BTC, ETH, SOL), mid-cap DeFi tokens, and high-volatility meme coins. The selection criterion is that the asset must be listed on at least 3~of the 6~target exchanges with sufficient spot trading volume to produce meaningful cross-exchange spread dynamics.

\subsection{Train/Test Split}

All collection windows before July~25, 2026 form the training set; July~25--28 forms the held-out test set. The split is strictly chronological (no shuffling), implemented as a \texttt{snapshot\_idx} cutoff at index~3584 on the Jul~22--28 collection run. This ensures no future information leaks into training.

The training set contains approximately 2.9~million (coin, exchange-pair, snapshot) feature rows after panel construction, spanning multiple multi-day collection windows from June--July 2026. Cross-sectional rows within a snapshot are structurally dependent (they share the same market state), so this row count should not be interpreted as independent samples.

\subsection{Live Paper-Trading Protocol}

For live validation, we run two independent paper-trading campaigns that process incoming collector data in real time with no access to future snapshots.

\subsubsection{Campaign A: Jul~30 (weekday)}

\begin{itemize}
    \item \textbf{Model}: 73-feature variant with orderbook fix (\texttt{outputs\_ob\_fix}).
    \item \textbf{Horizon}: $H = 2$ (predict 2~snapshots ahead).
    \item \textbf{Z-score window}: 120~snapshots.
    \item \textbf{Duration}: approximately 8~hours (Wednesday/Thursday).
    \item \textbf{Predictions scored}: 49,310 total; 5,054 filtered entries.
\end{itemize}

\subsubsection{Campaign B: Jul~31 (weekend)}

\begin{itemize}
    \item \textbf{Model}: 68-feature production model (\texttt{statarb\_lgbm.txt}).
    \item \textbf{Horizon}: $H = 1$ (predict next snapshot).
    \item \textbf{Z-score window}: 300~snapshots.
    \item \textbf{Duration}: approximately 8~hours of useful data (planned 12~hours; collector terminated at snapshot~264 due to a software error).
    \item \textbf{Warmup}: predictions become active after $\text{MIN\_PERIODS} = 90$ snapshots (approximately 2.5--3~hours).
    \item \textbf{Predictions scored}: 58,995 total; 8,775 filtered entries.
    \item \textbf{Settled trades}: 7,973 closed; 50 still open at session end.
\end{itemize}

Both campaigns use entry threshold $|\hat{z}| \geq 0.5$ and capacity constraint $\text{max\_open} = 50$. The two campaigns differ in model vintage, horizon, z-score window, and market regime (weekday vs weekend). We present them as independent stress tests of the research pipeline rather than a controlled experiment isolating any single variable.

\subsection{Baseline Definitions}

\subsubsection{Naive persistence}

On every row where the model generates a prediction, we also record the naive forecast $\hat{z}_{t+H} \leftarrow z_t$ (the current z-score predicts the future z-score unchanged). R$^2$ and directional accuracy are computed for both model and naive on the \emph{identical} rows, ensuring that any performance difference is attributable to the model rather than to row selection.

\subsubsection{Mechanical z-score baselines}

We replay two mechanical trading rules on the Jul~31 signal panel under the same capacity constraints ($\text{max\_open} = 50$) and settlement proxy as the model:

\begin{itemize}
    \item \textbf{Persistence}: enter when $|z_t| \geq 0.5$, direction $= \text{sign}(z_t)$.
    \item \textbf{Mean-reversion}: enter when $|z_t| \geq 0.5$, direction $= -\text{sign}(z_t)$.
\end{itemize}

These represent the two canonical directions a rule-based z-score system can take: betting the spread continues (persistence) or reverts (classical pairs trading). Both settle at $t+1$ with $\text{pnl\_proxy} = \text{direction} \times z_{t+1}$, identical to the model's settlement.

\subsection{Reproducibility}

The dataset is publicly available at \url{https://huggingface.co/datasets/SFU-fintech-AI/statarb-crypto-research}. The training notebook (\texttt{statarb/cex\_gbm\_new.ipynb}), live trader (\texttt{experiments/paper\_trade\_lgbm.py}), reporting scripts (\texttt{scripts/report\_paper\_session.py}, \texttt{scripts/portfolio\_sharpe\_paper\_session.py}), and campaign output directories are included in the repository. LightGBM training is reproducible given fixed seeds and the provided hyperparameters.
